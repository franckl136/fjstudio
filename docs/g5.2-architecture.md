# Architecture du parcours Courses

| Étape | Composant | Garantie observable |
|---|---|---|
| Identifier | SDK Supabase, SecureStore sur appareil, stockage SDK sur Web | Le démarrage contrôle l’échéance avant d’ouvrir la dernière association du compte. Le réveil d’une session déjà ouverte présente la limite mesurée en revue. La référence locale contient les UUID, le rôle et l’heure de vérification. |
| Ouvrir | SessionProvider puis OutboxProvider | Le compte, le foyer et la liste sélectionnent un document versionné. Une liste confirmée vide est distinguée du chargement initial. |
| Enregistrer un geste | CourseStore | L’instantané confirmé et les commandes qui le modifient partagent une valeur durable. L’interface publie la projection après confirmation de la transaction. |
| Persister | IndexedDB sur Web, valeur AsyncStorage par contexte sur mobile | Transaction entre onglets sur Web, sérialisation des lectures-écritures dans le runtime natif. L’OS, les quotas et une désinstallation restent des limites. |
| Envoyer | File avec bail, temporisation et UUID | Un envoi sans réponse garde son identité. Une commande en conflit est conservée. L’état de la connexion déclenche la reprise. |
| Appliquer | RPC PostgreSQL sous le rôle appelant | Le reçu et l’effet métier partagent une transaction. Deux gestes volontaires ont deux UUID. Un ajout agrégé renvoie l’article canonique. |
| Acquitter | CourseStore | Le reçu doit correspondre à l’opération et à sa portée. Le client persiste le résultat et la sortie de file ensemble. Un reçu tardif d’un ancien bail ne consomme pas une autre commande. |

Une coche porte l’état demandé. Un changement de quantité ou de libellé transporte les valeurs qu’il a réellement lues pour ces champs. Deux changements sur des champs distincts peuvent converger. Un conflit de même champ exige une résolution explicite. Une suppression crée une trace logique. Le traitement d’une ancienne commande ne recrée pas l’article. L’annulation d’une suppression et une nouvelle création sont deux gestes distincts.

L’export Expo embarque un service worker qui vérifie les empreintes du shell et de ses ressources publiques. Ce cache permet de rouvrir la route à froid. La liste et les opérations sont reconstruites par le magasin métier. Une première ouverture en ligne est nécessaire pour installer le shell, reconnaître le foyer et disposer d’un premier instantané.

La décision détaillée figure dans l’ADR-007 du dépôt mobile, avec les options SQLite, persistance du cache de requêtes et document métier versionné. Le choix garde des adaptateurs de plateforme derrière le même contrat de transaction.
