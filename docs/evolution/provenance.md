# Retrouver la source d’une information

| Question | Où lire la réponse |
|---|---|
| Qu’a contrôlé ce passage ? | Dans Quality Lab ou App Lab, lire le projet, la source, le fichier et le profil avant le lancement. La sélection manuelle fige la révision locale affichée. Dans l’historique, le lien **Commit** ouvre la révision intégrale du rapport. Chaque contrôle porte son état observé. |
| Ce PASS concerne-t-il le code du projet ? | Les deux exemples embarqués portent la mention de démonstration. Les bilans des profils de qualification acceptent des passages terminés sur une source autorisée du projet. L’audit statique concerne uniquement le fichier ou la photographie désignée. |
| D’où vient cette connaissance ? | Dans Project Intelligence, la fiche donne son origine, sa source, sa révision, le statut, l’acteur, la date et la confiance déclarée. Un import affiche le commit lorsqu’il a été enregistré et permet de relire en v1 le texte ou l’extrait importé. La confiance et le commit peuvent rester non renseignés. Une décision sur une proposition nécessite une action de validation. |
| Que prouve le catalogue de données ? | Database Explorer distingue déclaration d’une intégration dans un manifeste, schéma lu localement, import manuel, démonstration et connexion confirmée lors d’une capture. L’écran de qualité du schéma renvoie à sa version dans l’explorateur. |
| Qui a réellement travaillé ? | L’Agent Office reflète les contacts et baux des postes du Studio. Une session Cursor documentée reste consultable dans l’historique. Le journal donne l’heure et l’action, puis les identifiants disponibles dans le détail. |

Les versions anciennes d’une connaissance peuvent précéder l’enregistrement du commit documentaire. Dans ce cas, le Studio conserve la référence historique et affiche « Non documenté ». Une révision éditée peut différer du texte importé en v1.
